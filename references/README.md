# Intent Classification & Query Routing Reference Implementations

This directory houses three upstream open-source repositories used as reference
architectures for implementing `src/model_customization/unified_router/intent_classifier.py`.
Do not commit the cloned subdirectories to version control; only this `README.md` is tracked.

## 1. Setup: Pulling Reference Repositories

Run the following commands from the project root to populate this directory:

```bash
mkdir -p references
git clone --depth 1 https://github.com/aurelio-labs/semantic-router.git references/semantic-router
git clone --depth 1 https://github.com/lm-sys/RouteLLM.git references/RouteLLM
git clone --depth 1 https://github.com/huggingface/setfit.git references/setfit
```

Or simply run:

```bash
bash scripts/pull_references.sh
```

## 2. Reference Architecture Guide for the Agent

When implementing or refactoring `src/model_customization/unified_router/intent_classifier.py`,
inspect the following target files in the cloned repositories:

### Option A: Aurelio Labs semantic-router (Embedding Centroid / Similarity Routing)

- Repository: `references/semantic-router`
- Key Files to Inspect:
  - `semantic_router/route.py` (Route schema definition with sample utterances)
  - `semantic_router/layer.py` (RouteLayer similarity scoring, threshold calibration, and fallback logic)
  - `semantic_router/encoders/ollama.py` or `semantic_router/encoders/fastembed.py`
- How to Use: Either import `semantic_router` directly or adapt
  `RouteLayer._retrieve_top_route()` using our existing `nomic-embed-text` Ollama
  embeddings and FAISS store to classify queries into `SIMPLE_ML_BASELINE` vs.
  `COMPLEX_SLM_SQL`.

### Option B: LMSYS RouteLLM (Calibrated Complexity Threshold Routing)

- Repository: `references/RouteLLM`
- Key Files to Inspect:
  - `routellm/Controller.py` (Routing orchestration between weak/simple and strong/complex targets)
  - `routellm/routers/routers.py` (SimilarityWeightedRouter, MatrixFactorizationRouter, BERTRouter)
  - `routellm/routers/similarity_weighted/utils.py` (Cosine similarity weighted scoring against calibration queries)
- How to Use: Reference `SimilarityWeightedRouter` to calculate complexity scores against
  our golden evaluation queries generated by `save_car_queries.py` and
  `save_housing_queries.py`.

### Option C: Hugging Face SetFit (Contrastive Few-Shot Sentence Transformer)

- Repository: `references/setfit`
- Key Files to Inspect:
  - `src/setfit/modeling.py` (SetFitModel wrapper combining SentenceTransformer body with a scikit-learn LogisticRegression head)
  - `src/setfit/trainer.py` (SetFitTrainer contrastive pair generation for small datasets)
- How to Use: If embedding distance alone yields <95% routing accuracy on unit tests, use
  the `SetFitModel` pattern (embeddings + scikit-learn `LogisticRegression` saved to
  `src/artifacts/models/intent_classifier.pkl`) trained on 32 labeled simple/complex car and
  housing queries.

## 3. Production Contract Requirement

Regardless of which reference implementation is used under the hood,
`src/model_customization/unified_router/intent_classifier.py` must expose a strict
Pydantic-validated interface:

```python
from pydantic import BaseModel, Field
from enum import Enum


class QueryRouteType(str, Enum):
    SIMPLE_ML_BASELINE = "simple_ml_baseline"
    COMPLEX_SLM_SQL = "complex_slm_sql"


class IntentClassificationResult(BaseModel):
    route: QueryRouteType
    confidence: float = Field(ge=0.0, le=1.0)
    matched_reference_method: str
```
